## Примеры реализации шаблонов программирования в PHP с примерами из фреймворков .

ВНИМАНИЕ: структура классов в файлах - не соответствует: 1 класс = 1 файл(SOLID) Для наглядности 1 файл -  полная реализация: несколько классов и клиентский код. Не забываем про Single responsibility.
    

<details>
<summary><strong>Behavioral</strong></summary>
 
        -= : поведенческие паттерны : =-

 
 - Chain of Responsibilities - Шаблон Цепочка обязанностей, позволяет передавать запрос по цепочке потенциальных обработчиков, пока не будет найден подходящий
 
 - Command - Шаблон Команда, идеально подходит для задач логгирования и постановки в очередь. Он инкапсулирует запрос как объект, позволяя параметризовать клиентов различными запросами, ставить их в очередь и поддерживать отмену операций.
 
 - Interpreter - Шаблон, Интерпретатор, используется для определения представления грамматики и интерпретации выражений на этом языке.
 
 - Iterator - Шаблон Итератор, который предоставляет стандартный способ последовательного обхода элементов сложной коллекции без раскрытия ее внутреннего устройства.
 
 - Mediator - Шаблон, Посредник, инкапсулирует взаимодействие между объектами, уменьшая связанность.
 
 - Memento - Шаблон, Хранитель, позволяет сохранять и восстанавливать внутреннее состояние объекта без нарушения инкапсуляции.
 
 - Null Object - Шаблон, предоставляет "нулевую" реализацию интерфейса, которая ничего не делает, позволяя избежать проверок на null.
 
 - Observer - Шаблон, Наблюдатель, определяет зависимость "один-ко-много" между объектами, позволяя оповещать наблюдателей об изменениях.
 
 - Specification - Шаблон, Спецификация, позволяет создавать комбинируемые правила для проверки объектов
 
 - State - Шаблон, Состояние, позволяет объекту изменять свое поведение при изменении внутреннего состояния.
 
 - Strategy - Шаблон, Стратегия, инкапсулирует семейство алгоритмов и делает их взаимозаменяемыми.
 
 - Template Method - Шаблонный метод, определяет скелет алгоритма в базовом классе, позволяя подклассам переопределять отдельные шаги без изменения структуры алгоритма.
 
 - Visitor - Посетитель позволяет добавлять новые операции к существующим объектам без их изменения.
</details>
    

<details>
<summary><strong>Creational</strong></summary>

        -= : Порождающие паттерны : =-

 - Abstract Factory - шаблон, который предоставляет интерфейс для создания семейств связанных или зависимых объектов без указания их конкретных классов. Это "фабрика фабрик" - создает другие фабрики.

 - Builder - шаблон, который позволяет пошагово конструировать сложные объекты, избегая конструкторов с большим количеством параметров. Он отделяет конструирование объекта от его представления, позволяя создавать различные представления с одним и тем же процессом конструирования.

 - Factory Method - шаблон, который определяет интерфейс для создания объектов, но позволяет подклассам изменять тип создаваемых объектов. Это "виртуальный конструктор" - создает объекты, не указывая явно их классы.
(FactoryMethod - это когда базовый класс определяет фабричный метод, а подклассы реализуют его для создания конкретных объектов. Клиент работает с базовым классом, а создание делегируется подклассам.)

 - Multiton - это расширение Singleton, где вместо одного глобального экземпляра существует несколько именованных экземпляров. Каждый экземпляр доступен по уникальному имени (ключу) и может иметь разные состояния или конфигурации.

 - Object Pool - шаблон, который позволяет повторно использовать дорогостоящие в создании объекты, поддерживая пул ("pool") таких объектов. Вместо создания и уничтожения объектов каждый раз, они берутся из пула, используются, а затем возвращаются в пул для последующего использования.

 - Prototype - шаблон, который позволяет копировать объекты, не делая код зависимым от их классов. Вместо создания нового объекта через new, мы клонируем существующий объект (прототип) и модифицируем его по необходимости.

 - SimpleFactory (Простая фабрика) - шаблон, который предоставляет НЕстатический метод для создания объектов различных типов. Фабрика инкапсулирует логику создания объектов, скрывая от клиента конкретные классы.
(SimpleFactory - это один класс с НЕстатическим методом create(), который возвращает экземпляры различных классов. Клиент работает с фабрикой, а не с конкретными классами.)

 - Singleton - шаблон, который гарантирует существование только одного экземпляра класса и предоставляет глобальную точку доступа к нему. 

 - StaticFactory (Статическая фабрика) - шаблон, который предоставляет статический метод для создания объектов различных типов. В отличие от SimpleFactory, который, часто является отдельным классом с одним методом, но StaticFactory обычно является самим классом продукта, который предоставляет статический метод для создания экземпляров.

___

    SimpleFactory - это один класс с методом create(), который возвращает разные типы объектов. Клиент знает о фабрике, но не о конкретных классах.
    FactoryMethod - это когда базовый класс определяет фабричный метод, а подклассы реализуют его для создания конкретных объектов. Клиент работает с базовым классом, а создание делегируется подклассам.


### Разница между Builder и других порождающих паттернов:
 
    Builder = Пошаговое конструирование +Отделяет конструирование от представления +Для сложных объектов
  когда нужно создать сложный объект со множеством параметров, особенно если часть параметров опциональна или объект может иметь разные вариации.
 ___
    Factory Method = Создание одного объекта +Использует наследование +Для простых объектов
  когда заранее неизвестно, объекты какого конкретно класса вам понадобятся, но базовый класс должен делегировать создание подклассам.
 ___
    Abstract Factory = Создание семейства объектов +Использует композицию +Для связанных объектов
 когда нужно создавать семейства взаимосвязанных объектов, не привязываясь к их конкретным классам.
 ___
    Prototype = Клонирование объекта +Использует клонирование +Для клонирования
  когда создание нового объекта дороже или сложнее, чем копирование уже существующего.
 ___
    Singleton = Один экземпляр +Использует глобальный доступ +Для единственного объекта
  когда в приложении должен существовать ровно один экземпляр класса, и к нему нужен глобальный доступ.
___
</details>

<details>
<summary><strong>Structural</strong></summary>

        -= : Структурные паттерны : =-


 - Adapter - Шаблон Adapter(Wrapper - обертка) позволяет объектам с несовместимыми интерфейсами работать вместе.

 - Bridge - Шаблон Bridge (Мост) разделяет абстракцию от реализации, позволяя изменять их независимо. 

 - Composite - Шаблон Composite это взаимодействие с иерархической группой объектов также, как и с отдельно взятым экземпляром.

 - DataMapper - Шаблон DataMapper это ключевой шаблон для отделения бизнес-логики от хранения данных. Шаблон DataMapper разделяет объекты предметной области и базу данных, обеспечивая независимое изменение кода работы с данными и бизнес-логики.

 - Decorator - Шаблон Decorator позволяет динамически добавлять объектам новые обязанности, оборачивая их в декораторы. Это альтернатива наследованию и обеспечивает большую гибкость.

 - Dependency Injection (DI) - это техника, при которой зависимости объекта предоставляются извне, а не создаются самим объектом. Это позволяет снизить связанность кода и улучшить тестируемость.

 - Facade - это структурный шаблон, который предоставляет упрощенный интерфейс к сложной системе, библиотеке или фреймворку. Он скрывает внутреннюю сложность и позволяет взаимодействовать с системой через единый, понятный интерфейс.

 - Fluent Interface (также известный как Method Chaining) - это шаблон проектирования, который позволяет создавать более читаемый код, возвращая $this из методов, что позволяет вызывать методы в цепочке.

 - Flyweight - это структурный шаблон, который позволяет экономить память, разделяя как можно больше данных между похожими объектами. Он используется, когда нужно создавать большое количество объектов, потребляющих много памяти.

 - Proxy - Шаблон Proxy предоставляет объект-заместитель, который контролирует доступ(или упрощенное логгирование запросов/обращений) к другому объекту.

 - Registry - это структурный шаблон, который предоставляет глобальный контейнер для хранения и доступа к объектам. Он позволяет любому участку кода получать доступ к зарегистрированным объектам через централизованный реестр.

</details>
